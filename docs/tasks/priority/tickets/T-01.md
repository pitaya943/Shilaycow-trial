# T-01 儲存層:priority 欄位與舊檔就地升級

Status: done
Risk: high (改資料檔的資料表與開檔檢查,在 brief 的 Critical areas)
Scenarios: S-4、S-5
Design: ../design.md 的形狀 A

## 要做的

- `TodoStore` 存取 `priority`(`low`/`normal`/`high`,預設 `normal`);`Todo` 帶出它。
- 舊的四欄資料檔:開檔時就地加欄位,舊待辦都是 `normal`,標題、完成、到期日、編號序列不變。
- 欄位不是四欄也不是五欄、或不是這個服務寫的檔:照舊拒絕,不寫任何東西。
- 兩個 `TodoStore` 同時開同一個舊檔:兩個都成功。做法是把讀欄位與 ALTER 放在 `BEGIN IMMEDIATE` 裡(design.md)。這一項不放進下面的檢查:同時開檔靠時序,沒做也可能碰巧通過;驗收時讀程式碼確認。
- 既有測試比對整個 JSON 的地方,依設計加上 `"priority": "normal"`(若 T-01 改到回應);HTTP 層的新欄位輸入留給 T-02。

## 檢查(交票前已對目前程式跑過,失敗)

`python docs/tasks/priority/tickets/T-01-check.py` 印出 `T-01 check: OK`、exit 0。它用 `main` 版本的 store 寫一個舊檔(含一個已完成、一個有到期日的待辦),再用目前的 store 打開,檢查 S-5;並寫入 `low` 後重開,檢查 S-4。
