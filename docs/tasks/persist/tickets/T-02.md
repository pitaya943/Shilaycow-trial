# T-02 讀不了的資料檔與重啟的操作紀錄

Status: todo
情境:S-5;S-1 到 S-3 的實際重啟
依賴:T-01

## 要做到

照 `design.md` 的「讀不了的資料檔」:`TodoStore.__init__` 在寫入任何東西之前驗證檔案,不成立就丟 `StoreUnreadable`,訊息裡有檔案路徑,檔案不被更動。

`drive-todo-api` 多一段實際關掉再啟動行程的流程(S-1 到 S-3),以及一段資料檔是亂碼時啟動失敗的流程(S-5);把紀錄存到 `docs/tasks/persist/evidence/drive.txt`。動作用使用者做的事命名,不用情境編號。

## 檢查(沒有這個改動時每一項都必然失敗)

- 資料檔內容是亂碼:`TodoStore(path)` 丟 `StoreUnreadable`,訊息包含路徑,檔案的位元組和之前完全相同。
- 資料檔是一個 SQLite 資料庫,但裡面只有別的資料表:同樣丟 `StoreUnreadable`,檔案裡沒有多出 `todos` 表。
- 資料檔是一個 SQLite 資料庫,`todos` 表的欄位不對:同樣丟 `StoreUnreadable`。
- 長度為 0 的檔案:正常啟動,清單是空的。
- 實際操作:資料檔是亂碼時用工廠啟動指令啟動,行程以非 0 結束,輸出裡有 `StoreUnreadable` 與檔案路徑,檔案沒被動到。
- 實際操作:新增兩筆、把一筆標為完成、關掉行程、再啟動、列出仍是那兩筆、再新增一筆編號是 3。
- `drive.sh` 連跑兩次、埠被占用時再跑一次,結束後沒有殘留的行程,占用時 exit 1。
