# 待辦事項在重啟後還在

狀態:Owner 已核准(2026-11-21)。

## 目標

服務關掉再打開之後,之前新增的待辦、它們的到期日與完成狀態都還在。

## 不做什麼

- 刪除或修改待辦。
- 多台機器或多個服務同時共用同一份資料。
- 備份、匯出、匯入。
- 帳號與權限:所有人看到的是同一份清單。
- 標題長度的上限(Owner 在上一個任務合併後提出)。它會改變現有的行為,所以留給獨立的任務;見「假設」。

## 情境

### S-1 重啟後資料還在
Given 我新增了「繳電費」(到期日 2026-12-01)與「買牛奶」兩筆待辦
When 我把服務關掉再打開,然後列出待辦
Then 我看到同樣的兩筆,順序、編號、到期日都和關掉前一樣

### S-2 完成狀態也還在
Given 我把「買牛奶」標為完成
When 我把服務關掉再打開,然後列出待辦
Then 「買牛奶」仍然是已完成

### S-3 編號不會重複使用
Given 已經有編號 1 與 2 的待辦
When 我把服務關掉再打開,然後新增一筆
Then 新的這筆編號是 3

### S-4 第一次啟動
Given 從來沒有儲存過任何資料
When 我啟動服務並列出待辦
Then 服務正常啟動,清單是空的

### S-5 存的資料壞掉了
Given 儲存資料的檔案內容被弄壞(不是這個服務寫出來的格式)
When 我啟動服務
Then 服務不啟動,並明白告訴我是哪個檔案讀不了;那個檔案沒有被覆蓋或清空

### S-6 原本的功能不變
Given 前兩個任務的九個情境(新增、列出、標為完成、空白標題、不存在的編號、帶到期日、不帶到期日、只看逾期、到期日格式不對)
When 我照原本的方式操作
Then 結果都和以前一樣

## 怎麼試

用專案的 `drive-todo-api` 啟動服務,新增兩筆、把一筆標為完成,關掉服務再啟動,列出待辦確認都還在,再新增一筆確認編號接續。然後把資料檔的內容改成亂碼再啟動一次,確認服務拒絕啟動而且檔案沒被動到。

## 預算

2 小時、10 個 session。

## 謹慎程度

謹慎

## 假設(Owner 沒有說,我先這樣定)

- 資料存在服務所在機器上的一個檔案裡。預設放在啟動服務的目錄下,可以用設定指定別的位置。
- 一筆新增或標為完成,在服務回覆「成功」之前就已經寫進檔案;服務在回覆之後當掉,那筆也還在。
- 同一時間只有一個服務在用這個檔案。同時啟動第二個不在這個任務的範圍內。
- 兩個人同時新增時,兩筆都會存下來,編號不同。
- 資料永久保存,沒有自動清除,筆數沒有上限。
- 標題長度仍然沒有上限(和現在一樣)。現在它會被永久存下來,所以這個缺口比以前重要;建議下一個任務處理。
- 測試使用各自獨立的暫存資料檔,不會動到真正的資料檔。
